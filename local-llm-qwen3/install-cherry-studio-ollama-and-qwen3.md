# 🍒 Install Cherry Studio, Ollama and Qwen3

### 一、Cherry Studio 是什么

免费开源的桌面 LLM 客户端（中文界面友好），通过接入本地 Ollama 后端，提供**图形化对话 + 自带知识库（RAG）能力。核心价值：日常润色、写作、审稿回应都能在图形界面完成，且数据不出本机**。

### 二、配置步骤

#### 第 1 步：下载安装

* 官网：`cherry-ai.com`（GitHub 开源仓库也可下）
* 下载 Windows 版 → 安装 → 打开

#### 第 2 步：接入 Ollama 本地模型

1. 确认 Ollama 已启动（任务栏有 Ollama 图标，或 `ollama list` 能看到 `qwen3:14b`）；
2. Cherry Studio 界面：左下角 **「设置」→「模型提供商」**；
3. 找到 **Ollama**（通常已预置，无需填 API Key）；
4. 点「管理」→ 添加模型，输入 `qwen3:14b`（和 `qwen3:7b` 备用）；
5. 回到对话页，顶部模型下拉选 **qwen3:14b（Ollama）** 即可开始。

> ⚠️ **保密红线**：对话时确保选中的是 **Ollama 本地模型**。Cherry 也支持云端 API（如豆包、OpenAI），**处理稿件敏感内容时不要选云端通道**，否则数据会上传，保密性归零。

#### 第 3 步：新建知识库（RAG）导入综述 PDF

1. 左侧栏点 **「知识库」** → **「新建知识库」**；
2. 命名（如 `综述`），选择嵌入模型——建议本地嵌入（如 `BAAI/bge-large-zh`），避免用云端嵌入上传内容；
3. 把综述 PDF 直接拖入，Cherry 会自动切块并建向量索引；
4. 对话页勾选该知识库，提问时自动检索相关文献片段再回答。

#### 第 4 步：日常使用

* **润色/写作**：直接对话，贴入段落要求润色或续写；
* **审稿回应**：用提示词模板（Cherry 支持保存模板）套"审稿意见 | 我们回应 | 修改位置"三栏格式；
* **检索问答**：勾选知识库后问"这篇综述里关于跨被试数据泄露风险的主要论据有哪些"。

***

### 三、Cherry Studio 与 rag.py 分工

两者**不是替代，是互补**。按你的诉求选：

| 场景                    | 用 Cherry Studio | 用 rag.py | 说明                         |
| --------------------- | --------------- | -------- | -------------------------- |
| 日常对话润色、写作             | ✅               | ❌        | Cherry 界面快、有模板，适合高频小任务     |
| 综述 PDF 快速问答（临时）       | ✅               | ❌        | 拖入即用，省事                    |
| **严格可核验的引用检索**        | ⚠️              | ✅        | 脚本输出更可控，可加检索来源追溯           |
| **批量核验引用是否真实**        | ❌               | ⚠️       | 脚本可扩展，但核验真实性需接百晓/Consensus |
| 自动化 / 脚本化处理           | ❌               | ✅        | 脚本可定时、可批处理、可嵌进工作流          |
| 最严格保密（不进任何 GUI 的云端嵌入） | ⚠️              | ✅        | 脚本纯本地，嵌入也本地，最干净            |

#### 推荐组合

* **主力日常**：Cherry Studio（本地 Ollama 通道）+ 知识库；
* **核验/批量**：保留 `rag.py` 用于需要可复现、可追溯检索结果的场景；
* **真伪核验**：引用是否存在，用 **Consensus / 百晓** 逐条查（GUI 和脚本都做不了这个）。

***

### 四、关键提醒（严谨起见）

1. **嵌入模型也选本地**：Cherry 建知识库时若默认用云端嵌入 API，上传的 PDF 内容会发给云端。务必选本地嵌入模型，保持零外传。
2. **对话通道确认**：每次处理敏感内容前，看一眼模型下拉是否还是 Ollama 本地模型。
3. **显存**：Cherry 只是客户端，推理仍走 Ollama，显存占用规则不变（14B 约 9–10GB，勿上 32B）。
4. **知识库≠引用核验**：Cherry 检索到的是"你 PDF 里已有的内容"，它**不能**告诉你某条引用在真实文献里是否存在——真伪核验仍要靠学术检索工具。

***

### 五、一句话结论

> **Cherry Studio 接本地 Ollama（qwen3:14b）+ 本地嵌入建知识库** = 图形化 + 保密的日常写作与检索方案；`rag.py` 保留用于需可复现检索的批量场景；引用真伪核验另用 Consensus/百晓。三者的共同底线是**敏感稿件内容绝不走云端通道**。
